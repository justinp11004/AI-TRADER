# SOURCE AUTHORITY — what beats what

When sources conflict, this order decides. Machine-readable mirror: `source-precedence.json`.

1. **Constitution** — the 18 prime laws (rendered in SYSTEM → Config & Laws; enforced in the server boundary). Locked entries (`LAW-004` 5R floor, `LAW-007` 19/19, `GOV-024` token) are editable by no path in any UI.
2. **Runtime config** — single numeric truth. If prose and config disagree, config wins (LAW-015).
3. **Canonical schemas** — packet, vote, decision-enum, order, position shapes. Ad-hoc UI objects never override them.
4. **Agent hierarchy & playbooks** — 34 seats, 8 groups, 5 vetoes; playbook FSMs.
5. **Current operating doctrine** — the domain content extracted from V7–V10 (packet sections, autopsy method, envelope law, compounding gates).
6. **Implementation intent** — the production rebuild spec (this repo's docs).
7. **The legacy HTML files** — *visual and interaction reference only* (`legacy/reference/`).
8. **Older layers/snapshots** — research and lineage only.

Additional rules:
- The frontend never overrides the backend. The UI renders verdicts; it never computes authority.
- Historical profitability or visual appeal never overrides a safety control.
- Legacy content marked lineage cannot silently override current rules.
